# POINT Orchestra — 로컬 에이전트 작업실

총괄·UI·개발·리뷰/테스트의 별도 터미널과 실제 Codex 작업을 연결하는 로컬 도구입니다. 네 터미널은 하나의 메시지 서버를 사용하며, 대시보드는 같은 실행 이력을 표시합니다. 창을 열기만 해서는 모델 작업을 실행하지 않습니다.

## 실행

프로젝트 루트의 PowerShell에서:

```powershell
.\tools\orchestra\start.ps1
```

Python 3.12+와 로그인된 기존 Codex CLI가 필요합니다. 추가 Python 패키지나 외부 서비스 설치는 없습니다. 서버는 `127.0.0.1:8765`에만 연결합니다. 실행하면 역할별 터미널 네 개와 브라우저가 열립니다.

```powershell
# 서버만 시작 (자동 테스트나 기존 터미널 이용)
.\tools\orchestra\start.ps1 -NoTerminals -NoBrowser
# 서버·진행 중 작업 종료, 기록은 보존
.\tools\orchestra\stop.ps1
```

PowerShell 실행 정책을 자동으로 바꾸거나 우회하지 않습니다. 정책이 스크립트를 막으면 다음과 같이 기존 Python으로 서버와 역할별 터미널을 각각 실행할 수도 있습니다.

```powershell
python tools/orchestra/server.py
python tools/orchestra/terminal.py --role coordinator
python tools/orchestra/terminal.py --role ui
python tools/orchestra/terminal.py --role developer
python tools/orchestra/terminal.py --role reviewer
```

## 메시지 보내기

터미널에 일반 문장을 입력하면 그 역할에게 사용자의 작업 요청을 보냅니다. 다른 역할에게 전달하려면:

```text
/to ui 현재 상태를 보고하고 미결정 사항을 정리해줘.
/to developer UI가 전달한 결과를 읽고 구현 가능성을 검토해줘.
/to reviewer 이 작업 결과를 독립 검토하고 총괄에게 보고해줘.
/report coordinator 검토가 끝났습니다. 변경 파일과 검증 결과는 다음과 같습니다.
/status
/cancel 작업ID
/quit
```

`/to`는 수신 에이전트의 실제 Codex 실행을 예약합니다. `/report`는 받은 편지함에 저장하며 모델 실행을 유발하지 않습니다. `/quit`는 해당 터미널 보기만 닫습니다. 서버와 작업을 끝내려면 `stop.ps1`을 사용하세요.

대시보드에서도 수신 역할과 작업/보고 유형을 선택해 보낼 수 있습니다. 예시 버튼은 입력란만 채우며 전송하지 않습니다. 작업 지시를 전송하면 기존 Codex 계정 사용량을 사용합니다.

## 실제 실행과 화면의 관계

- 서버가 역할별 큐를 관리하고 실제 `codex exec` 프로세스를 시작합니다. 동일 역할에는 한 번에 한 작업만 배정하고 전체 동시 실행 수는 최대 3개입니다.
- 터미널 네 개는 각 역할의 입력·로그 창입니다. Codex는 작업이 있을 때 서버의 자식 프로세스로 실행되며, 대기 중에 네 모델이 계속 실행되는 구조는 아닙니다.
- 총괄 터미널의 coordinator는 이 Codex 앱 대화와 별도의 실행입니다. 이 대화의 모든 문맥이 자동 복제되지 않습니다. 프로젝트 운영 문서와 작업 메시지를 근거로 수행합니다.
- 각 작업은 새 Codex 실행입니다. 서버에 저장한 최근 역할 문맥을 전달하지만 이전 CLI 세션 전체를 재개하지는 않습니다.
- 에이전트가 구조화된 결과에 작업 인계나 보고를 반환하면 서버가 실제 수신자에게 전달합니다. 결과 보고는 추가 모델 실행을 자동으로 유발하지 않으므로, 총괄의 후속 판단은 새 작업 지시로 요청합니다.
- 작업 완료는 해당 실행이 결과를 반환했다는 뜻입니다. 제품 기능의 독립 검토·테스트 통과를 뜻하지 않습니다. 검토자는 별도로 배정해야 합니다.
- 움직임은 실제 실행 상태에 연결됩니다. 연결 끊김·실패·취소를 완료로 표시하지 않습니다. 자동 인계 횟수에는 제한이 있어 무한 호출을 막습니다.

## 권한과 보존

기본 모드는 읽기 전용 Codex 작업입니다. 실제 파일 구현을 배정하려면 서버를 종료한 뒤 `start.ps1 -WorkspaceWrite`로 실행합니다. 이 모드에서도 총괄·리뷰는 읽기 전용이며 UI·개발에만 workspace-write를 적용합니다. 작업 지시에 담당 파일과 승인 범위를 명시해야 합니다. 파일 소유권은 에이전트 지침으로 제한하며, 운영체제가 역할별 파일을 각각 격리하는 방식은 아닙니다. 미승인 POINT 앱 스택·UI를 임의 선택하도록 지시하지 마세요. 전역 Codex 설정, Windows ACL, 샌드박스를 변경하거나 우회하지 않습니다.

로컬 실행 기록은 `.orchestra/`에 저장하고 Git에서 제외합니다. 메시지 DB·실행 로그·연결 토큰에는 작업 내용이 포함될 수 있습니다. 실행 중인 서버는 새로고침 후에도 기록을 유지하고, 재시작 시 중단된 작업을 자동 재실행하지 않습니다. 정적 대시보드와 API는 같은 로컬 주소에서 제공됩니다.

## 검증

```powershell
python -m unittest discover -s tools/orchestra/tests -v
```

자동 테스트의 모의 실행과 실제 Codex 검증은 구분합니다. 자동 테스트 통과만으로 계정 인증·실제 모델 응답·Windows 창 표시를 검증했다고 주장하지 않습니다. 현재 실제 검증 결과는 `PROJECT_STATUS.md`의 작업실 구현 결과에 기록합니다.
