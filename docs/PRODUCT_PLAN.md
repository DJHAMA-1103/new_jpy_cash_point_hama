# POINT iPhone 첫 버전 개발 계획

기준: 2026-09-14. 총괄 작성. D-008~D-011과 최신 사용자 지시 기준.

## 확정된 목표

- iPhone을 먼저 개발해 사용자 반응을 확인한다.
- 첫 버전은 일본어로 제공하고 문구 리소스를 분리해 후속 언어 추가에 대비한다.
- 사용자가 보유한 결제·포인트 앱을 등록하고, 매장에 도착하면 해당 매장에서 사용할 수 있는 등록 앱을 알림으로 안내한다.
- 알림에서 결제·포인트 앱 실행으로 이어져 계산대에서 앱을 찾는 시간을 줄인다.
- 첫 사용에 위치 사용 목적 설명과 권한 요청을 포함한다. 알림 권한은 별도로 안내한다.
- 주요 단계 완료 때 총괄이 전문 에이전트 결과와 검증 결과를 시각화해 보고한다.

## 단계와 완료 기준

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1. 제품 기반 | 일본어 문구, 명확히 구분한 샘플 카탈로그, 기술·화면 제안 | JSON 및 ID 참조 검증, 독립 문구·데이터 검토 |
| 2. 실행 가능한 첫 UI | 보유 앱 선택·저장, 매장 검색·상세, 설정, 권한 상태 화면 | 선택 앱과 지원 앱의 교집합·저장·빈 상태·일본어 화면 테스트 |
| 3. iPhone 네이티브 연결 | 위치·알림·앱 실행 인터페이스의 실제 iOS 구현 | Mac/Xcode와 실제 iPhone에서 허용·거부·앱 전환·백그라운드 검증 |
| 4. 제한된 실제 매장 시범 | 검증된 매장·지원 앱 데이터, 사용자 피드백 흐름 | 지원 정보 출처 및 앱 실행 링크 확인, 사용자 시나리오 검증 |
| 5. 배포 준비 | 실제 기능에 맞는 스토어 자료·개인정보 설명 | 별도 배포 준비 승인 및 최종 검토 |

단계 1의 샘플은 실제 매장이나 결제 앱의 지원 정보를 보장하지 않는다. 실제 위치 감지·알림·딥링크 동작을 시뮬레이션 성공으로 대체하지 않는다.

## 구현 제안과 미결정 사항

- 스택 제안: 기존 설치된 Flutter + Dart. 사용자 응답 대기. SwiftUI 대안과 구분한다.
- UI 제안: 밝은 배경, 진한 녹색 주요 버튼, 하단 `近くのお店 / マイアプリ / 設定` 3탭. 사용자 응답 대기.
- 사용자 앱 선택은 수동으로 시작하며 iPhone 설치 앱 전체 자동 탐지를 가정하지 않는다.
- 앱 ID 목록은 샘플 카탈로그와 별도로 저장한다. 실제 데이터와 검증되지 않은 샘플을 혼합해 표시하지 않는다.
- 위치·알림 권한 상태는 독립 관리한다. 거절한 사용자에게 수동 매장 검색을 제공하는 방향을 제안한다.
- 알림 탭에서 매장 상세로 진입해 앱을 선택하는 흐름과 대상 앱을 직접 여는 흐름의 최종 정책은 실제 iOS 검증과 함께 확정한다.
- 초기 실제 매장 범위·데이터 출처·실행 링크·중복 알림 제한 정책은 미결정이다.
- 무료·유료·프리미엄 기능 및 가격은 미결정이다. 아직 구독·광고·결제 기능을 추가하지 않는다.

## 역할 분담과 검토

- 총괄: 요구사항·우선순위·파일 소유권·상태·승인 기록·결과 취합.
- 개발: 샘플 카탈로그, 승인된 스택의 앱 구현. 맡은 파일만 변경.
- UI/UX: 일본어 문구·화면 구조. 화면 결과는 개발과 테스트의 검토를 받음.
- 코드 리뷰·디버그·테스트: 구현 이후 각 역할로 교대하고 독립 검증.
- 환경 문제는 실제 개발을 막을 때만 조사한다. 설정 로딩 추가 연구를 개발 선행조건으로 삼지 않는다.

## 검증 경계

- 데이터 검증: 샘플 표시, 고유 ID, 유효 참조, 실행 URL 미설정 안전 처리.
- UI·도메인 검증: 선택·해제·저장, 교집합, 세 가지 빈 상태, 일본어 긴 문구.
- 실기기 필수: 실제 위치·백그라운드·잠금·알림·앱 실행·권한 변경·VoiceOver.
- Windows에서 실행한 단위·UI 검사를 iPhone 빌드 또는 실기기 통과로 기록하지 않는다.
